## 2024-05-18 - Fix Deprecated Cryptographic Functions
**Vulnerability:** The codebase was using `crypto.createCipher` and `crypto.createDecipher` which derive deterministic keys and IVs from a password using an outdated algorithm (EVP_BytesToKey with MD5). Reusing IVs in authenticated encryption modes like AES-GCM is a catastrophic security failure because it completely breaks the encryption.
**Learning:** Legacy cryptographic practices persist when upgrading APIs is perceived as difficult. When replacing deprecated encryption routines, it's critical to write backwards-compatible fallbacks within the decryption logic that handle older ciphertexts securely while generating cryptographically secure properties (like an explicitly random IV) for new encryptions.
**Prevention:** Avoid deprecated native cryptography functions. Utilize high-level, maintained abstraction libraries (e.g., node-sodium) or specifically enforce `crypto.createCipheriv` along with securely generated, unique random IVs per encryption call. Ensure robust regression testing for cipher text compatibility when upgrading cryptographic routines.
