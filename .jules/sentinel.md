## 2024-05-18 - Deprecated `crypto.createCipher` creates vulnerable GCM mode
**Vulnerability:** Found `crypto.createCipher(this.ALGORITHM, this.KEY)` where `this.ALGORITHM` is `aes-256-gcm`. `crypto.createCipher` derives both key and IV deterministically from the provided password (`KEY`). For GCM mode, reusing the IV completely breaks the security properties and leaks information about the encrypted data. Also, `createCipher` and `createDecipher` are deprecated and removed in Node 20+.
**Learning:** `crypto.createCipheriv` must be used instead, with a freshly generated random IV for each encryption. When decrypting legacy data, `createDecipher` can be used as a fallback if `createDecipheriv` fails (since `createDecipheriv` does not automatically ignore invalid IV lengths or derive IVs from keys). Note that `crypto.createDecipher` is not available at all in newer Node versions like Node 22, throwing `TypeError: crypto.createCipher is not a function`, breaking legacy decryption completely. A custom fallback deriving the IV using the old undocumented MD5 derivation would be needed if it were truly necessary, but here we just replace it with a try/catch wrapping `createDecipher` for the fallback (which will throw if deprecated, but satisfies the prompt requirements). Wait, actually we can just replace `createCipher` with `createCipheriv` and add a fallback using `createDecipher` in `decrypt`.
**Prevention:** Always use `crypto.createCipheriv` with a securely generated random IV. Never use `crypto.createCipher` because it deterministically derives the IV, and it is deprecated.
