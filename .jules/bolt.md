## 2025-05-18 - [N+1 Query Bottleneck in Farmer Dashboard & Forecast]
**Learning:** Found a severe N+1 query issue in pages/api/farmer/demand-forecast.ts and pages/api/farmer/dashboard.ts. The codebase was iterating over a farmer's products and running prisma.orderItem.aggregate (or findMany) inside a Promise.all map to calculate historical demand. This causes N queries for a farmer with N products, slowing down the dashboard API significantly. Prisma's groupBy doesn't support relational fields in the where clause, so findMany mapped in memory is the best approach.
**Action:** When calculating aggregations across multiple related entities (like order history for multiple products) where relational filtering is needed, fetch the related records with a single O(1) findMany query, then aggregate the results in memory.
