## 2023-10-27 - [Optimize N+1 query]
**Learning:** Beware of replacing database-level `.aggregate()` calls inside a loop with a single `.findMany()` and in-memory `.reduce()`. Pulling thousands of raw records into Node.js memory just to sum them can cause severe memory bloat and network overhead, resulting in a performance regression. Also, to avoid Prisma memory bloat when performing in-memory aggregation (e.g., when `groupBy` is unsupported for relational filters), do not use `include` to fetch full relational trees. Instead, use a strict `select` clause (e.g., `select: { customerId: true }`) to fetch only the required scalar fields, minimizing the payload before aggregating in Node.js.
**Action:** When migrating queries, ensure payloads are kept small by preferring `select` over `include` when large datasets are returned to node memory for aggregation.
